# 概念体裁（concept-landscape）

## 本体裁适用范围

问题的主体是**理解一个概念 / 现象 / 系统**："什么是 X / 为什么会有 X / X 和 Y 什么区别 / X 的直觉"。概念题里出现公式（如注意力的 QKV）**不改变体裁**——公式在本体裁里只是佐料。

- 正例："什么是 KV cache？"（容量公式作佐料）/ "为什么大模型会幻觉？" / "RAG 是什么，和微调什么区别？"
- 反例（应路由到推导体裁）："REINFORCE 的梯度公式帮我推导一下" / "PPO 的 clip 项为什么这么设计？"

若尚未完成体裁裁定，先回 SKILL.md 执行"第一步：体裁裁定"，再读本文件。**本文件是本体裁的唯一生成依据。**

## 概念教学法（四条铁律，全程强制执行）

> 一句话总结：**一个隐喻讲到底，先见图后进词，章章有图跟全程，误解破了才算懂，公式只当佐料。**

1. **一个核心隐喻贯穿**：选一个能承载概念**主要矛盾**的生活场景（对应推导体裁的"一个玩具例子贯穿"），第 1 章把它立起来，第 2 章起每个组件的讲解都要**回收隐喻的语言**——中途换隐喻、或第 2 章起隐喻消失变成干讲义，均视为违规。辅助类比至少两个，每个对应一个真难点。好隐喻必须声明**失效边界**：专设一小节（通常第 1 章末）写清"隐喻在哪里和事实分叉"，防止隐喻自带新的错误模型；边界小节引用尚未讲到的概念时，引用处必须带一句话白话，禁止裸前向引用（如"语义相似度（第 2 章）"须补半句它是什么）。

2. **图景优先**：第 2 章先给一张 SVG **全景组件图**，让读者先看见整体再进局部；每个组件回答两问："它干嘛的" + "为什么需要它在场"。禁止开篇堆术语——术语只在组件登场时按需引入，且**首现即配白话；该纪律适用于正文、表头、表格单元格、SVG 图内标签、图注**（附录词典是复习点，不是首次解释点）。

3. **误解纠偏**：至少 3 条"误解 vs 真相"。这是概念课件的**啊哈时刻**——读者带入的错误心智模型被当面打破，比正面灌输有力得多。误解必须来自初学者真实踩坑（高频、具体），不是稻草人。

4. **公式是佐料不是主菜**：概念确需公式佐证时（KV cache 的容量估算、注意力的 QKV）：出场前一句人话说明它干嘛，出场后逐项翻译——但**不展开推导、不做数字实算、不做闭环验证**。课件结尾"延伸"一节：指向同站已有的推导课件（若有），或一句话建议"想看这条公式的逐步推导，可以直接发起推导题"（本地/无部署模式下无从查询云端课件清单，直接用兜底话术即可，不必探测）。

5. **图示跟满全程**：图不是第 2 章的仪式——第 1～5 章每章至少一张信息性 SVG（第 0 章与附录除外）。按内容选型：剧场章配场景示意或"两种世界"对比图；组件章配全景图——**概念本身是流程 / 管道（RAG、Agent）画流程图，是结构 / 组成（MoE、Transformer 层）画分层结构图**；误解章配"错误 vs 正确心智模型"对照图；对比章配概念版图 / 坐标定位图；边界章配决策树或频谱图。**两条硬规则：凡出现具体数字对比（容量、成本、量级）必配数量级对比图；凡出现时间线 / 演进叙述必配时间轴图。**

## 工作流程（本体裁）

1. **判定深度**：概念体裁的深度旋钮是**类比密度与术语密度**——问题越基础，隐喻越多、术语越晚出场；问题越专业，可以更快进入架构语言。铁律 1–4 不因深浅豁免。
2. **运行三环引擎**：直觉环（定义 → 核心隐喻 → 概念锚点）、图景环（全景组件图设计 → 组件故事化——隐喻语言贯穿）、原理环（公式佐料按需迟到，不展开）。
3. **生成 HTML 课件**：按下方骨架生成，写入 `工作区/<领域>/<主题>.html`；交付形态、HTML 技术要求、站点聚合发布、对话导读等共享规范见 SKILL.md「交付形态」一节。

## 课件骨架（七幕，按此组织章节）

```
第 0 章   一句话核心（30 秒版，先给终点）+ 先修自检（2–4 条**每个词条带一句白话**的前置概念；必须覆盖本课件机制层的"心脏地基"——如训练、向量、参数；**第 0 章内部顺序：一句话核心 → 先修自检 → 之后正文术语才准出场**）
第 1 章   生活剧场（核心隐喻展开，概念在场景中流动、遇到麻烦、被解决；配场景示意/对比图；章末声明隐喻失效边界）
第 2 章   图景拆解（SVG 全景组件图 + 逐组件"干嘛 + 为什么在"，沿用第 1 章隐喻语言）
第 3 章   常见误解与真相（≥3 条，warning 卡片 + 误解/真相对照表；可配"错误 vs 正确心智模型"对照图）
第 4 章   邻居概念对比表（最强易混者；维度：本质一句话 / 形象类比 / 何时用它 / 不用它会怎样；旁配概念版图 / 坐标定位 SVG）
第 5 章   适用边界（什么时候需要它 / 什么时候不需要，过度使用的陷阱；可配决策树或频谱图；工程深水区——选型参数、并行/通信细节——放折叠块或标注"选读"，不挡概念读者主线）
合卷      自查三问（3 道合卷题，考察主线与误解纠偏，参考答案折叠）
附录      术语一句话词典（15–30 条为宜，宁精勿滥）
```

## 卡片编排（沿用共享类名，禁止自创）

- `.intuition`：人话、核心隐喻、组件白话解释；
- `.warning`：误解条目、适用边界陷阱；
- `.aha`：真相揭晓、顿悟时刻（误解被打破的瞬间）；
- `.formula`：佐料公式（出现即先人话、逐项翻译）；
- `.number`：仅当确有小数字说明（如容量量级对比）时使用，非必须；边界：至多一次代入（一步乘除可接受）、只取量级、无中间竖式；
- 对比表用样式化 HTML `<table>`（样式已在共享 CSS 内）。

## 输出规范（本体裁）

- **结构强制**：七幕齐全（第 0 章到附录），禁止省略或合并；第 4 章对比表强制。
- **结尾自查三问**：结尾设 3 道合卷自查题（考察主线与误解纠偏，参考答案放折叠块）。
- **四条铁律强制**：隐喻贯穿、图景优先、误解纠偏、公式佐料——写作全程逐条自查，交付前对照检查清单核验。
- **篇幅**：参考区间约 400–700 行（HTML 源码行数；"每章一图"使 SVG 行占比上升，已计入）——判据是七幕**讲透**：行数不足时补深度（误解纠偏、对比维度、适用边界），禁止拆行或注水凑数。
- 文件交付、分块写入、零脚本、LaTeX、共享样式、站点发布、对话导读等共享规范，一律见 SKILL.md「交付形态」。

## 宽松变体（论文精读 / 工程实战暂栖于此）

- **论文精读**：第 1 章剧场 → "论文用一句话 + 一张图讲什么"；第 2 章图景拆解 → 方法拆解（论文自己的架构图）；第 4 章对比表 → 与最强基线/前作对比；第 5 章适用边界 → 局限与适用范围；误解纠偏保留（对论文的常见误读）。
- **工程实战**：第 2 章图景拆解 → 方案组件拆解（架构图 + 每个组件的选型理由）；第 5 章适用边界 → 选型边界与成本量级；对比表 → 竞品方案对比；核心隐喻降为引子即可。
- 完整体裁（独立骨架与铁律）后续按需扩展，扩展方式：新增 `references/genre-<名称>.md` + SKILL.md 路由表加一行。
