# 代码编写规则（Coding Rules）

适用团队全部源代码，示例以 Java 呈现，规则语言无关（无可见性修饰符的语言按惯用约定对应）。违反【强制】条款不得合入主干；新代码立即执行，存量代码"谁触碰、谁迁移"。

## 规则零：动手之前，先读完整规则【强制】

写码、改码、评审前必须先完整阅读本文件，以仓库内 `CODING_RULES.md` 为唯一权威版本。凭记忆、印象或转述动手即违规。若读到的内容出现省略占位符、章节编号不连续等截断迹象，视为规则不完整，必须先读取文件全文再动手。AI 编码代理同守此条。

## 规则一：标识符禁止使用单词缩写【强制】

类、函数、变量、常量、参数、包名一律使用完整英文单词。

| 禁止 | 应为 |
| --- | --- |
| `msg` / `usr` / `cnt` / `btn` / `cb` / `req` / `resp` / `cfg` | `message` / `user` / `count` / `button` / `callback` / `request` / `response` / `configuration` |

豁免：业界通用术语（`id`、`url`、`json`、`dto` 等）、循环下标 `i/j/k`、第三方库既有命名。

## 规则二：单行最长 160，超长则对称折行【强制】

未超限的语句禁止人为折行。超过 160 字符时采用悬挂式换行，按模板执行：

```java
// 调用与定义：每个参数独占一行，收尾括号单独成行并与首行左对齐
subscriptionService.renewSubscriptionForUser(
    originalSubscriber,
    renewalPlan,
    billingCycle,
    prorationPolicy,
    effectiveDate,
    notifyUserByEmail,
    allowPartialRenewal
);

public Subscription renew(
    User subscriber,
    Plan renewalPlan,
    BillingCycle billingCycle
) {
    return gateway.submit(subscriber, renewalPlan, billingCycle);
}

// 长条件：运算符前置，每个子条件独占一行
if (
    subscription.isExpired()
    && policy.allowsRenewal(subscription, renewalPlan)
    && effectiveDate.isBefore(expiredDate)
) {
    sendReminder(subscription);
}

// 链式调用：在 "." 之前断开，每个环节独占一行
List<Summary> summaries = records.stream()
    .filter(record -> record.isPaid())
    .map(OrderRecord::toSummary)
    .collect(Collectors.toList());
```

要点：参数一旦换行必须全部逐行排列，禁止首行塞满仅溢出折行；续行缩进 4 空格；一次只折一层结构。无法分割的长字面量（URL 等）允许超限，但应提取为常量。

## 规则三：类结构固定分区【强制】

成员排列顺序：常量 → 静态变量 → 实例变量 → 构造函数 → 生命周期方法 → 普通方法。各分区内可见性从高到低：`public → protected → private`。

空行纪律【强制】：字段与字段之间、函数与函数之间，各空一行。

```java
public class OrderService {

    public static final int MAX_ITEMS_PER_ORDER = 200;

    private final OrderRepository orderRepository;

    public OrderService(OrderRepository orderRepository) {
        this.orderRepository = orderRepository;
    }

    public Order createOrder(User buyer, List<OrderItem> items) {
        validate(items);

        Order order = new Order(buyer, items);
        return orderRepository.save(order);
    }

    private void validate(List<OrderItem> items) {
        if (items.size() > MAX_ITEMS_PER_ORDER) {
            throw new IllegalArgumentException("order items exceed the limit");
        }
    }
}
```

单个类超过约 20 个方法或 800 行时，应结合规则四评估拆分【推荐】。

## 规则四：类名与职责精确匹配【强制】

类名 = 领域名词 + 角色后缀（`Service`、`Repository`、`Controller`、`Factory`、`Validator`、`Converter`、`Client` 等），必须能一句话说清该类负责什么。

- 禁止过泛：`Manager`、`Helper`、`Util`、`Common`、`Data`、`Info` 兜底命名；工具类须限定功能域（`DateRangeUtils` 可以，`CommonUtils` 禁止）；
- 禁止过细：类名不得含实现细节或多重动作（`UserEmailPasswordLoginService` → `LoginService` + `PasswordLoginStrategy`）；
- 自检：更换实现方式后类名依然成立，才算合格。

## 规则五：函数体内按逻辑分段，段间空一行【强制】

一段 = 一个可命名的步骤（校验、计算、保存）。相邻逻辑段空一行；连续多个空行同样禁止；一两行的短函数不分段。逻辑段超过 4 段或某段需要注释说明用途时，优先提取私有方法，方法名即注释。

## 规则六：Java 优先使用 Lombok【强制】

用注解替代手写样板：`@Data`（DTO/VO）、`@Value`（不可变对象）、`@Builder`（复杂构建）、`@Slf4j`（日志）、`@RequiredArgsConstructor`（注入构造器）、`@UtilityClass`（常量类）。

边界【强制】：

- JPA/Hibernate 实体禁止 `@Data`（equals/hashCode 触碰懒加载关联），改用 `@Getter` + `@Setter`；
- 继承体系需 `@EqualsAndHashCode(callSuper = true)`；继承 + 建造者用 `@SuperBuilder`；
- 定制方法直接手写（Lombok 遇同名方法自动跳过）；
- `@Builder` 吞无参构造器，需框架反射创建时补 `@NoArgsConstructor`。

```java
@Data
public class OrderCreateRequest {
    private String orderNumber;
    private String remark;
}

@Slf4j
@RequiredArgsConstructor
public class NotificationService {
    private final MailClient mailClient;
}
```
